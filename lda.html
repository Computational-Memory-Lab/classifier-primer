LDA, from the ground up

Linear discriminant analysis is the classifier this lab uses most, and it is usually described in one sentence: it draws a line between two groups. That sentence is true and almost useless.

No machine learning assumed. Every symbol is defined where it first appears. The companion page, SVM, from the ground up, has the same eleven sections in the same order, so you can read them side by side and see exactly where the two models agree and where they part. Sections 1, 2 and 8 are deliberately near-identical between the two.

0The short version

LDA assumes each of your two groups is a cloud of points with the same shape, differing only in where its centre sits. Under that assumption there is a provably best way to separate them, and LDA computes it directly — no search, no iteration, no tuning. It takes the line joining the two centres and then corrects it for the fact that some directions in the data are naturally noisy and others are quiet. The correction is the entire method — and also where the trouble starts, because computing it takes more data than a memory experiment produces.

1What one trial looks like to the model

A participant sees a word. We record voltage from electrodes on the scalp. For our study-phase analysis we look at 10 electrodes and cut the 1,200 ms after word onset into 12 time bins of 100 ms each, averaging the voltage inside every bin. The bins run end to end and do not overlap, so each one is a separate slice of the trial. That gives 10 × 12 = 120 numbers for each word.

Those 120 numbers are the trial, as far as the model is concerned. The model never sees a scalp, a waveform, or a word. It sees a list of 120 numbers per trial. In the notation everyone uses, the whole list is called x, and the individual numbers in it are x1, x2, … x120 — so "feature 47" is x47. How many of them there are is called p, so here p = 120.

Each trial also carries a label: was that word later remembered, or later forgotten? Two possibilities, so we write the label as y = 1 or y = 0. The two groups those labels carve the trials into — all the remembered ones, all the forgotten ones — are the classes. Classifying a trial means deciding which of the two it belongs to, and the word never means more than that.

A participant studies 225 words, so that participant gives us 225 trials — and a trial is an entire list of 120 numbers with one label attached, not a single number. Laid out flat, one participant's data is a table of 225 rows × 120 columns — 27,000 voltage values — beside a column of 225 labels. Every row is one studied word; every column is one feature. The number of trials is written n, so here n = 225 and p = 120.

A feature is one of those 120 numbers — one electrode at one time bin. "Feature 47" means something concrete: the average voltage at, say, electrode 4 during time bin 7. When a model "puts weight on a feature", it multiplies that one number by something. Each feature is an x with a number on it, and p counts them rather than naming one: p = the number of features = 120.

The shape of one participant's data
A weight is one number per column; a prediction is made from one row. Cross-validation holds some rows back, so only about 202 of them are ever trained on — and the whole small-sample problem is that 202 rows have to pin down 120 weights.

2What a weight is

LDA and SVM produce the same kind of object at the end. They differ in how they choose it, not in what it is.

The model produces one number per feature. Those numbers are the weights, written w1, w2, … w120. To classify a new trial, multiply each feature (x1 … x120) by its weight (w1 … w120), add them all up, and add one final constant b called the bias or intercept:

score = w1x1 + w2x2 + … + w120x120 + b written compactly as score = wᵀx + b

If the score comes out positive, predict "remembered". If negative, predict "forgotten". That is the whole prediction rule. It is a weighted sum and a comparison against zero.

So a weight is a multiplier applied to one feature, and the set of 120 of them is the entire learned content of the model. When we say a classifier was "trained", we mean: those 120 weights plus b were chosen. When we say it is "linear", we mean the score is a weighted sum with no squares, products, or thresholds inside it.

Which axis the weights live on. There are 120 weights because there are 120 features — one per electrode-and-time-bin — and the same 120 are applied to every trial. There is no weight per trial. Look back at the table of one participant's data above: a weight belongs to a column, and the weighted sum collapses those columns into a single score for one row at a time.

Trials are not absent from this; they enter differently. Every training trial helps estimate each of the 120 weights, by a procedure that averages trials together feature by feature, but what comes out is still indexed by feature. Trials are what you learn from and what you later score one at a time, never what the weights are counted in.

The geometry, in two dimensions

With 120 features you cannot picture this, so picture two. Each trial is a dot on a page. The rule "w1x1 + w2x2 + b = 0" is a straight line across that page. Trials on one side score positive, trials on the other score negative. The weights control the line's direction; the bias b slides it back and forth without rotating it.

With 120 features the same thing happens in a 120-dimensional space, and the dividing surface is a hyperplane — the flat thing one dimension below whatever space you are in. Nothing about the arithmetic changes. Only your ability to visualize it does.

Why exactly one dimension below: the boundary is one equation, and one equation fixes one feature. Solve "score = 0" for the last feature and you get x120 = −(w1x1 + … + w119x119 + b) / w120. Choose the other 119 however you like and the last one is then decided for you. 119 free choices is what makes it 119-dimensional. The same count on a page: choose x1, and x2 is forced — one free choice, a line.

The weights are also a direction. The weight vector w also points in a direction — the direction perpendicular to that dividing line. Moving along that direction changes the score fastest. So "what the classifier learned" and "which direction through the data separates the classes" are the same statement.

3What LDA is trying to make true

LDA starts from an assumption about how the data were generated, and then derives the best possible rule under that assumption. That is unusual: it is not searching for a line that works well. It is computing the line that would be provably optimal if the data fits the model's assumptions.

The assumption

Three parts, and each one is also a way the model can fail.

  1. Each class is a Gaussian cloud. "Gaussian" (or "normal", or "bell-shaped") means values pile up around a centre and thin out symmetrically. In 120 dimensions it means the trials of one class form a fuzzy ellipsoidal blob.
  2. Both clouds have the same shape. They can sit in different places, but they must be stretched and tilted identically. This is the assumption that makes LDA linear — drop it and you get a curved boundary instead: quadratic discriminant analysis.
  3. We know that shape and those centres. We do not. We estimate them from the data, and nearly everything that goes wrong with LDA traces back to that estimate.

What "the shape of a cloud" means numerically

The shape is described by a table called the covariance matrix, written Σ. It has one row and one column per feature, so for us it is 120 × 120. Where row i meets column j sits a single number describing how features i and j vary. That number means one of two things depending on where you look:

  • On the diagonal — the 120 entries where a feature meets itself: row 7 against column 7, and so on. Each is how much that one feature varies across trials, on its own. A noisy electrode has a big number here.
  • Off the diagonal — every one of the other 14,280 entries, where i and j are two different features. Each says whether those two move together. Two neighbouring electrodes pick up much of the same activity, so when one goes up the other usually does too: a large positive entry. Two time bins from the same electrode do the same thing.

This matters enormously for EEG specifically. Neighbouring electrodes are not independent measurements — the skull smears each underlying source across many sensors, so a single source shows up on a dozen electrodes at once. The off-diagonal entries of Σ are large, and any method that ignores them is throwing away most of what it knows about the data.

Σ for one participant, all 120 × 120 of it

The rule that follows

Given those assumptions, the mathematically optimal decision is: assign a trial to whichever class it is more likely to have come from — remembered or forgotten. Working that through for two Gaussians with equal covariance — this is the derivation in Welch (1939) — everything nonlinear cancels, and what survives is exactly a weighted sum of the features, with weights

w = Σ−1 (μ1 − μ0) Blankertz et al. (2011), Eq. 9 — the whole of LDA in one line

That w is the weights — the same ones from earlier, all 120 at once. The formula does not produce something weight-adjacent that then has to be converted; hand it a set of trials and what comes back is w1 … w120, ready to drop straight into the score. Writing it as a single letter is just shorthand for the whole list, the way x was shorthand for one trial's 120 numbers.

It is built from two pieces.

  • μ1 − μ0 is the separation. A class centre is the average trial of a class. Take every remembered trial and average them feature by feature: the 120 numbers you get back describe one imaginary typical remembered trial, and that is μ1. The forgotten trials give you μ0. Each is a point sitting in the same 120-dimensional space as a real trial — just not a trial anybody recorded. Subtracting one from the other says, feature by feature, how far apart the two classes sit.
  • Σ−1 divides that by the noise. The raised −1 means inverse, and an inverse is a reciprocal: for an ordinary number, 4−1 is ¼, and multiplying by ¼ is the same as dividing by 4. So Σ−1 is how you divide by Σ. A gap between the classes only counts for as much as the noise it has to be seen against. With a single feature no matrix is involved at all: Σ is that feature's variance σ2, Σ−1 is 1/σ2, and the formula reads (μ1 − μ0) ÷ σ2 — the gap, divided by how much that feature varies anyway. The matrix inverse is what that division turns into when there are 120 features that also vary together: the nearest thing a matrix has to a reciprocal, defined so that multiplying by Σ and then by Σ−1 gets you back where you started.

So the formula reads as separation, divided by noise. That is the entire method for the 120 weights.

Where b comes from

The weights set the boundary's direction and leave it free to sit anywhere. The bias b is the single number that decides where along that direction it actually sits, and it is built from two pieces added together.

b = −wᵀ(μ1 + μ0)/2  +  ln(π1/π0) put the boundary between the two centres, then shift it for how common each class is
  • The first piece centres it. (μ1 + μ0)/2 is the midpoint between the two class centres. Scoring that midpoint and subtracting the answer puts the boundary exactly there, so a trial sitting halfway between the two classes scores zero. Without it the boundary would pass through the origin, which is wherever the recording equipment happened to put zero volts.
  • The second piece accounts for how common each class is. π1 and π0 are the prior probabilities — the chance a trial belongs to each class before you look at the EEG at all. That is each class's share of the trials, so it comes from counting and dividing. Participant 58 has 143 remembered and 82 forgotten, 225 in total, so π1 = 143 ÷ 225 = 0.64 and π0 = 82 ÷ 225 = 0.36. Being two shares of the same 225 trials they add to 1. The term is then ln(0.64 ÷ 0.36) = +0.56, where ln is the natural logarithm — what it contributes here is a number that is 0 when the two classes are equally common, positive when class 1 is the commoner one, and further from 0 the more lopsided the split gets. It is positive, which nudges every score toward "remembered" — correctly, because a trial you know nothing about is more likely to be a remembered one.

4How each weight actually gets its value

Take that formula apart in the order a person would compute it.

Part 1 — the difference of means

Average all the remembered trials, feature by feature: 120 numbers, one per feature. Average all the forgotten trials the same way: another 120. Then subtract them feature by feature — feature 1's remembered average minus feature 1's forgotten average, feature 2's minus feature 2's, and so on through feature 120. Each subtraction stays inside its own feature; nothing is ever compared across electrodes or across time bins. You now have 120 numbers, each saying how much bigger this one feature is, on average, when the word was later remembered.

If you stopped here and used those differences as the weights, you would have a perfectly reasonable classifier. It has a name — the nearest-centroid or Euclidean classifier — and it is the yellow line in the figure below. It says: weight each feature by how much it differs between conditions.

Part 2 — why that is wrong, and what Σ−1 fixes

The difference of means treats all 120 features as separate, independent pieces of evidence. They are not. Suppose two adjacent electrodes both show the remembered-minus-forgotten difference. Is that two independent votes for "remembered"? Almost certainly not — it is more likely one underlying source seen twice. Counting it twice overstates the evidence.

Multiplying by Σ−1 is the correction. It does two things at once:

  • It divides by noise. A difference of 1 µV along a direction where trials naturally scatter by 10 µV is worthless. The same difference along a direction where trials scatter by 0.5 µV is strong evidence. The inverse covariance downweights the first and upweights the second.
  • It removes double-counting. Two electrodes correlating at 0.9 are largely one measurement made twice. The difference of means gives each its own weight, so that single piece of evidence enters the score twice at full strength. Σ−1 subtracts from each feature the part its correlated neighbours already account for: with two features of equal variance and correlation r, the weight on the first comes out proportional to (d1 − r·d2) instead of just d1, where the d's are their two differences. Give both features the same difference and set r = 0.9, and each weight lands at about half what it would be if the two were independent — so the pair contributes roughly what one feature alone would. Not a tenth, which is the tempting guess: the subtraction does leave only d − 0.9d = a tenth of the raw difference, but the whole expression is then divided by (1 − r2) = 0.19, which is the variance the two features share being handed back. 0.1 ÷ 0.19 = 0.53.

A useful way to hold it: Σ−1 stretches the space until all the noise is round and equal in every direction — a transformation called whitening — finds the straightforward difference-of-means line in that stretched space, then maps the answer back. In the stretched space the naive rule is correct; the multiplication is what gets you there and back.

Part 3 — so where does one individual weight come from?

The answer surprises people:

A weight is not a measure of how informative its feature is. A feature carrying no class information at all can receive a large weight — and removing it can make the classifier substantially worse.

Blankertz et al. (2011) demonstrate this with a constructed example. Take two electrodes, FCz and CPz, which both genuinely differ between the two classes. A classifier on those two gets 15% error.

Now add a source of alpha rhythm at electrode Oz — activity that has nothing to do with the task and is identical in both classes. Because of volume conduction it leaks into the other two electrodes, at 0.4 into CPz and 0.2 into FCz. Classification on FCz and CPz collapses from 15% error to 37%: the leaked alpha is pure added noise, and it more than doubles the error.

Add Oz as a third feature and the error returns to about 16% — essentially where it started. Oz alone is useless: it contains no class information whatsoever, and a classifier given only Oz would perform at chance. But it contains a clean measurement of the contaminant, so the classifier gives it a weight whose job is to subtract the alpha back out of the other two channels.

This is what Σ−1 buys, and it is why a weight cannot be read as importance. A weight is one coefficient in a noise-cancelling recipe. Its value depends on every other feature in the set. Change which features you include and every weight changes.

5A worked example you can check by hand

Two features, so it fits on a page. Suppose across many trials we measure:

  • Forgotten trials centre at μ0 = (0, 0).
  • Remembered trials centre at μ1 = (1, 1). So the difference of means is (1, 1) — both features shifted equally.
  • Both features scatter with variance 1, and they are correlated at 0.9 — they mostly move together.

Those three numbers are already Σ, once you know where each one sits. Σ has one row and one column per feature, so with two features it is a 2 × 2 grid of four numbers:

Σ = [[1, 0.9], [0.9, 1]] read as [[top-left, top-right], [bottom-left, bottom-right]]
  • Top-left is where row 1 meets column 1 — feature 1 against itself, which is its own variance. That is the 1.
  • Bottom-right is feature 2 against itself: the other 1.
  • The two off-diagonal entries are feature 1 against feature 2, which is their covariance — correlation multiplied by both standard deviations. Variance 1 means a standard deviation of 1 for each, so the covariance is 0.9 × 1 × 1 = 0.9, and the correlation and the covariance happen to be the same number here. They would not be if the variances were not 1.
  • Both off-diagonal entries are 0.9 because "how 1 moves with 2" and "how 2 moves with 1" are the same question. Σ is always symmetric across its diagonal.

The naive answer weights both features equally: w = (1, 1).

The LDA answer inverts Σ first. An inverse is the matrix version of a reciprocal: dividing by 4 is multiplying by ¼, and "dividing by Σ" is multiplying by Σ−1. For the shape we have here, [[a, b], [b, a]], there is a recipe with two steps.

  1. Flip the sign of the two off-diagonal entries, leaving the diagonal alone: [[1, 0.9], [0.9, 1]] becomes [[1, −0.9], [−0.9, 1]].
  2. Divide every one of the four entries by a² − b², which here is 1 − 0.81 = 0.19. Dividing a matrix by a number means dividing each entry separately: 1 ÷ 0.19 = 5.26, and −0.9 ÷ 0.19 = −4.74.
Σ−1 = [[1, −0.9], [−0.9, 1]] ÷ 0.19 = [[5.26, −4.74], [−4.74, 5.26]]

Now multiply that by the difference of means, (1, 1). Multiplying a matrix by a pair of numbers has its own rule, and it is only addition and multiplication: to get the first number of the answer, take the first row of the matrix, pair its entries with the pair you are multiplying, multiply each pair together, and add. Then do the same with the second row to get the second number.

first number = 5.26 × 1 + (−4.74) × 1 = 0.53
second number = (−4.74) × 1 + 5.26 × 1 = 0.53 row 1 against (1, 1), then row 2 against (1, 1)
w = (0.53, 0.53) same direction as the naive answer, but only 0.53 as large

Here the direction happens to be unchanged, because the setup is symmetric — but the magnitude collapsed to about half. That is LDA saying: these two features are 90% redundant, so a difference showing up in both is worth roughly one feature's worth of evidence, not two.

Now change one thing. Let the difference of means be (1, 0) — feature 1 shifts, feature 2 does not — with the same correlated Σ. Then:

w = (5.26 × 1 + (−4.74) × 0,   −4.74 × 1 + 5.26 × 0) = (5.26, −4.74)

Feature 2 shows zero difference between the classes and receives a large negative weight. This is the Oz effect in miniature. Because the two features move together, feature 2 is a good measurement of the shared fluctuation, and subtracting it cleans up feature 1. The naive rule would have given feature 2 a weight of exactly zero and thrown that away.

6The knob: shrinkage, and why it exists

Everything so far assumed we know Σ. We do not — we estimate it from the training trials, and that estimate is the weak point of the whole method.

Count what has to be estimated. A 120 × 120 covariance matrix is symmetric, so the number of distinct quantities in it is 120 × 121 ÷ 2 = 7,260. We estimate all 7,260 from about 202 trials. That is not a shortage of data; it is a different order of magnitude.

To see what that does, take the easiest case there is: suppose the truth is a perfectly round cloud. Every feature has variance 1, and no pair of features correlates at all. There is nothing subtle to discover — 120 ones down the diagonal, 7,140 zeros off it.

Round means the cloud is equally wide whichever way you measure across it, and you may measure any way you like. A direction is any mixture of the 120 features: feature 3 on its own is one, so is feature 3 minus feature 47, and so is any other combination. Each has a variance — how far the trials scatter along it — and the full set of those variances is what "the shape of the cloud" means. For a true sphere every one of them is 1.

Now draw 202 trials from exactly that sphere and measure. Go looking for the direction the trials scatter along most, and its variance comes out at 3.1. Go looking for the one they scatter along least, and it comes out at 0.06. The true answer was 1.0 both times.

Average those measured variances over all directions and you get 1.00, which is correct. So the average is right and the shape is wrong. On these measurements the cloud is fifty times wider in one direction than another. It is really a sphere.

Nothing in the 202 trials can catch that. A cloud that genuinely was fifty times longer one way would have produced the same numbers.

How the estimate fails — specifically

It does not fail by being randomly wrong in all directions. It fails in a systematic, predictable way, and knowing the direction of the error is what makes the fix possible.

With too few trials, the estimated covariance overstates the large variances and understates the small ones. The estimated cloud looks more elongated than the true one.

That happens because those directions are not handed to you — they are found, by searching the sample for the direction along which the trials happen to spread most. A search over many candidates lands on one that got lucky, so the winner's measured variance is larger than any true variance. Run the search for the smallest and it lands on one that got unlucky. Roll 120 dice: the highest beats the average and the lowest trails it, not because any die is loaded but because you went looking for the extremes. Every individual number is fine on average, which is why the total comes out right. It is the spread across directions that is manufactured, and the spread is the shape.

Why that is catastrophic here: LDA uses Σ−1, and inverting turns the small numbers into large ones. The directions estimated as having very little variance become directions the inverse multiplies by an enormous factor. If one of those small values is small mostly by accident, the classifier will place huge weight on a direction that is pure noise. Blankertz et al. show this directly: with 200 features, the estimated variance spectrum from 50 samples is wildly too steep at both ends, and the fit only approaches the truth around 500 samples.

The fix

Shrinkage. Rather than trusting the measured covariance, mix it with a simple, stable stand-in — a perfectly round cloud whose size is the average of the measured variances:

Σ(Γ) = (1 − Γ) × Σmeasured + Γ × νI Blankertz et al. (2011), Eq. 12; ν is the average variance, I the round stand-in

Γ runs from 0 to 1 and is the only tuning parameter LDA has:

Γwhat the model believesthe weights become
0the measured covariance, completelya full noise-cancelling filter
betweenpartly — pulled toward rounda filter, damped
1features are unrelated to each other, though still individually noisyeach feature's difference divided by its own variance

Γ = 1 throws away every off-diagonal entry of Σ. What survives is each feature's difference scaled by how noisy that feature is on its own — a sensible rule, and one that is blind to every relationship between features.

The reason every Oz-style weight collapses to zero is mechanical. Strip the off-diagonal entries and Σ is left with nothing but variances down its diagonal, and the inverse of such a matrix is just the reciprocal of each variance, in place. Multiplying by it therefore does one thing per feature and never mixes two: weight i becomes di ÷ σi2, its own difference over its own variance. A feature whose two classes have identical means has di = 0, so its weight is 0 ÷ something, which is 0 — however useful it would have been for cleaning up a different feature. Oz earned its weight entirely by correlating with FCz and CPz, and a correlation between two features is recorded nowhere except the off-diagonal entry that has just been deleted. The rule cannot subtract Oz from CPz because it can no longer represent the idea that the two share anything.

Two different things get called Γ = 1. The formula above shrinks the covariance toward νI — a sphere — so at Γ = 1 every feature is treated as equally noisy and the weights become the raw difference of means. That is Blankertz et al.'s convention. MATLAB's fitcdiscr, which is what our pipeline runs, shrinks the correlation matrix toward the identity and keeps each feature's own variance. So our Γ = 1 gives difference-of-means divided by variance, not the raw difference.

Which invites a fair objection: dividing the difference by the noise is what LDA was doing all along, so what has been lost? Σ−1 was doing two jobs, and only one survives. Dividing each feature by its own variance is the first, and it handles this electrode is noisy. Discounting evidence that two features share is the second, and it handles these two electrodes are the same measurement twice. Γ = 1 keeps the first and destroys the second. Both rules can honestly be called "difference divided by noise"; they differ in what noise is taken to mean — one feature's own scatter, or the joint structure across all 120. Both conventions discard all cross-feature structure, which is the point that matters here; they differ only in whether the surviving weights are still scaled per feature. The live figure above follows MATLAB's convention, so it matches our pipeline.

The elegant part is that the mixing weight can be computed rather than tuned. Ledoit & Wolf (2004), in the form given by Schäfer & Strimmer (2005), derive the Γ that minimises expected error directly from the data, with no cross-validation. That combination is what people mean by "shrinkage LDA".

Our pipeline runs Γ = 1 — the maximum, the row that discards all covariance structure. In Blankertz et al.'s own sweep, Γ = 1 was the worst setting they tried (36% error, against 18% at Γ = 0.05). We are not necessarily wrong to use it: at 1.7 trials per weight there may be nothing trustworthy to keep, and Raudys & Jain's sample-size table says a means-only classifier needs about a third the data of a full one. But it is a real choice with a real cost, and the trial-count work exists partly to price it.

7Reading the weights — the mistake almost everyone makes

You have a trained classifier. You have 120 weights. The natural next move is to plot them on a scalp map and say where in the brain the memory effect lives.

That is invalid.

There are two different maps, and they answer different questions.

The Oz example earlier is exactly this: Oz gets a big weight in the filter and is flat in the pattern. Reading the filter as a brain map would put a memory effect in occipital cortex, when what is actually there is alpha rhythm being subtracted out.

Haufe et al. (2014) is the standard treatment, and it gives a conversion between the two columns: multiply a trained model's weights by the covariance and what comes back is the interpretable map.

pattern = Σ w Haufe et al. (2014) — the map you are allowed to read

For LDA it is one line. The weights are w = Σ−1(μ1 − μ0). Multiply by Σ and the Σ meets the Σ−1 and the two cancel, exactly as multiplying by 4 cancels a division by 4 — leaving μ1 − μ0, the difference of means. Multiplying the weights back by the covariance undoes the division that made them uninterpretable, and hands back the ERP map you started from.

Which raises the obvious question of why anyone needs the formula, since for LDA it returns something you already had. The answer is that most linear models do not hand you a difference of means. Logistic regression, a linear SVM, the last layer of a network — all produce weights and nothing else, and for those there is no map lying around to fall back on. Σw is how you get one, and it is the same Σ estimated from the training data. The general rule:

Interpret patterns. Evaluate filters. If you want to say where in the brain something happens, plot the difference of means. If you want to know whether the information is decodable at all, use the classifier's accuracy. Never read the weight vector as anatomy.

The two conventions differ here in a way that is easy to get backwards. Under the shrink-toward-a-sphere convention, Γ = 1 makes the filter equal the pattern — the weight map becomes the difference of means and is safe to read. Under MATLAB's convention, which is ours, Γ = 1 makes the filter the pattern divided by each feature's variance: much closer to interpretable than a full filter, but still not a difference map, and still capable of exaggerating a quiet feature. Either way the direction of the trade is the same — the settings whose weights are easiest to interpret are the ones that have thrown away the most information.

8What breaks when trials are scarce

The classifier has to pin down 120 weights from about 202 trials — fewer than two trials per weight.

That ratio invites an immediate objection, and the objection is correct: every weight is computed from all 202 trials, and the data is not being divided up between them. The ratio measures something else — how much room the model has to bend. 202 trials are 202 constraints; 120 weights are 120 numbers free to take any value at all. What is left over after the fitting, 82 trials' worth, is the only thing standing between a rule that has found a pattern and a rule that has memorised this particular sample.

How little that is has a sharp statement. In 120 dimensions, any 121 points can be split perfectly by some hyperplane, whatever labels you attach to them — including labels you produced by flipping a coin. A rule with 120 weights can separate 121 arbitrary trials into two groups with zero training errors and have learned exactly nothing. We have 202, which is not far above 121. Fitting the training data is therefore weak evidence of anything, which is why every number on this page comes from held-out trials.

What that leaves is a learned direction that is the true direction plus estimation noise, and with p features and n trials the noise grows like p/n. Both halves of that expression are doing something. Each weight is estimated from n trials, so each one carries an error that shrinks like 1/n — the ordinary rule that averaging more data helps. But there are p weights, and the direction they define is wrong if any of them is wrong. The errors accumulate across all p of them, so the total squared error in the direction is p individual errors each of size 1/n: p/n. Adding a feature adds signal, but it also adds one more number to get wrong, and the second effect is the one that scales.

Raudys & Jain (1991) worked out the sample sizes needed to keep this under control. To keep expected error within 50% of its best achievable value:

That 1.2-versus-4.0 gap is the entire case for shrinkage, derived analytically decades before we measured the same thing by simulation. Raudys & Jain do not tabulate the middle row — diagonal LDA is not one of the classifiers they costed — but it estimates 120 numbers more than the Euclidean rule and 7,260 fewer than the full one, so it necessarily sits between them.

9Assumptions, variants, and failure modes

If the classes are not Gaussian

LDA is fairly forgiving here — it tends to work on non-Gaussian data because the rule only depends on means and covariances, not the full shape. But it is genuinely wrong when a class is multi-modal: if "remembered" is really two different processes with two different signatures, their average is a point between them that may describe no actual trial.

For our data specifically: our real EEG features are strongly non-Gaussian. Measured kurtosis is about 23, where a Gaussian is 3 — meaning far more extreme values than the model expects. That is a known gap between our simulations and our data.

If the two classes have different shapes

Then the optimal boundary is curved, and the model for it is quadratic discriminant analysis (QDA), which estimates a separate covariance per class. It is more flexible and almost always worse in practice here, because it doubles an estimation problem that is already hopeless. Raudys & Jain put its appetite at between 10 and 32 times the number of features — for our 120, somewhere between 1,200 and 3,840 trials, against the 202 we have. Blankertz et al. checked the equal-shape assumption for ERP data and found it approximately satisfied, which is the empirical justification for staying with LDA.

If the classes are unbalanced

Our study-phase data is: 143 remembered against 82 forgotten for participant 58, and lopsided in the same direction for nearly everyone. That imbalance goes into the prior term of b, which is exactly what that term is for. Left to itself the model leans toward predicting the common class, and it is right to: guessing "remembered" every time would be correct 64% of the time.

AUC is unaffected by b, though the claim is narrower than it sounds. AUC is computed from the order the trials are ranked in, and adding the same constant to every score cannot reorder anything. So no value of b changes AUC at all — while a single accuracy figure moves a great deal with it, which is one reason accuracy is a poor measure here.

That does not make the imbalance harmless. b is not the only thing it touches. The minority class has 82 trials to estimate its centre from rather than 143, so that centre is the noisier of the two, and the direction w inherits the error. Cross-validation makes it worse: split 82 trials ten ways and some folds carry eight examples of the class you are trying to detect.

That is what SMOTE is for — it synthesises extra minority trials so training sees a balanced set — and it addresses the estimate of w, not the invariance of AUC to b. Whether it helps is a separate question from whether it is well motivated, and on our own 62-subject replication of this dataset it does not: mean AUC goes from 0.531 to 0.526 for LDA and 0.520 to 0.521 for SVM. At this effect size, resampling the training set neither rescues the classifier nor damages it.

Things LDA is secretly the same as

  • Fisher's discriminant. Fisher (1936) asked for the direction maximising between-class separation over within-class spread, with no probability model at all, and got the same answer. Two derivations, one formula.
  • Least-squares regression on the labels. Regressing a 0/1 label on the features gives the same direction, up to scale.

Practical notes

  • Feature scaling does not matter. Σ−1 already normalises by variance, so rescaling a feature rescales its weight and leaves the answer unchanged. This is not true of SVM, whose assumptions section says why.
  • It is deterministic. Same data, same answer, every time — no random initialisation, no seed. Our committed LDA reference file has never changed; the SVM one had to be regenerated.
  • It is fast, and one-shot. Compute two means, one covariance, invert it. No iteration.
  • It gives calibrated probabilities under its assumptions, which SVM does not.
