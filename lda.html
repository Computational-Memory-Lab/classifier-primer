LDA, from the ground up

Linear discriminant analysis is the classifier this lab uses most, and it is usually described in one sentence: it draws a line between two groups. That sentence is true and almost useless. This page is the long version.

No machine learning assumed. Every symbol is defined where it first appears. The companion page, SVM, from the ground up, has the same eleven sections in the same order, so you can read them side by side and see exactly where the two models agree and where they part. Sections 1, 2 and 8 are deliberately near-identical between the two pages — that shared ground is the point, not an oversight.

0The short version

LDA assumes each of your two groups is a cloud of points with the same shape, differing only in where its centre sits. Under that assumption there is a provably best way to separate them, and LDA computes it directly — no search, no iteration, no tuning. It takes the line joining the two centres and then corrects it for the fact that some directions in the data are naturally noisy and others are quiet. The correction is the entire method. Everything else on this page is either what that correction is, or what goes wrong when you do not have enough data to work it out.

1What one trial looks like to the model

Start with what the classifier is handed, because none of the rest makes sense without it.

A participant sees a word. We record voltage from electrodes on the scalp. For our study-phase analysis we look at 10 electrodes and chop the time after word onset into 12 time bins, averaging the voltage inside each bin. That gives 10 × 12 = 120 numbers for each word.

Those 120 numbers are the trial, as far as the model is concerned. The model never sees a scalp, a waveform, or a word. It sees a list of 120 numbers per trial. In the notation everyone uses, the whole list is called x, and the individual numbers in it are x1, x2, … x120 — so "feature 47" is x47. How many of them there are is called p, so here p = 120.

Each trial also carries a label: was that word later remembered, or later forgotten? Two possibilities, so we write the label as y = 1 or y = 0. The two groups those labels carve the trials into — all the remembered ones, all the forgotten ones — are the classes. Classifying a trial means deciding which of the two it belongs to, and every "class" on this page means one of those groups, nothing more.

A participant studies 225 words, so that participant gives us 225 trials — and a trial is an entire list of 120 numbers with one label attached, not a single number. Laid out flat, one participant's data is a table of 225 rows × 120 columns — 27,000 voltage values — beside a column of 225 labels. Every row is one studied word; every column is one feature. The number of trials is written n, so here n = 225 and p = 120.

A feature is one of those 120 numbers — one electrode at one time bin. "Feature 47" means something concrete: the average voltage at, say, electrode 4 during time bin 7. When this page says a model "puts weight on a feature", it means it multiplies that one number by something. Each feature is an x with a number on it, and p counts them rather than naming one: p = the number of features = 120.

The shape of one participant's data
Everything below happens inside this table. A weight is one number per column; a prediction is made from one row. Cross-validation holds some rows back, so only about 202 of them are ever trained on — and the whole small-sample problem is that 202 rows have to pin down 120 weights.

2What a weight is

Both models on these two pages — LDA here, SVM on the other page — produce the same kind of object at the end. They differ in how they choose it, not in what it is. So it is worth being precise about what it is.

The model produces one number per feature. Those numbers are the weights, written w1, w2, … w120. To classify a new trial, multiply each feature (x1 … x120) by its weight (w1 … w120), add them all up, and add one final constant b called the bias or intercept:

score = w1x1 + w2x2 + … + w120x120 + b written compactly as score = wᵀx + b

If the score comes out positive, predict "remembered". If negative, predict "forgotten". That is the whole prediction rule. It is a weighted sum and a comparison against zero.

So a weight is a multiplier applied to one feature, and the set of 120 of them is the entire learned content of the model. When we say a classifier was "trained", we mean: those 120 weights plus b were chosen. When we say it is "linear", we mean the score is a weighted sum with no squares, products, or thresholds inside it.

Which axis the weights live on. There are 120 weights because there are 120 features — one per electrode-and-time-bin — and the same 120 are applied to every trial. There is no weight per trial. Look back at the table of one participant's data above: a weight belongs to a column, and the weighted sum collapses those columns into a single score for one row at a time.

Trials are not absent from this; they enter differently. Every training trial helps estimate each of the 120 weights, by a procedure that averages trials together feature by feature, but what comes out is still indexed by feature. Trials are what you learn from and what you later score one at a time, never what the weights are counted in.

The geometry, once, because it makes the rest readable

With 120 features you cannot picture this, so picture two. Each trial is a dot on a page. The rule "w1x1 + w2x2 + b = 0" is a straight line across that page. Trials on one side score positive, trials on the other score negative. The weights control the line's direction; the bias b slides it back and forth without rotating it.

With 120 features the same thing happens in a 120-dimensional space, and the dividing surface is a hyperplane — the flat thing one dimension below whatever space you are in. Nothing about the arithmetic changes. Only your ability to visualize it does.

One dimension below, and not by convention: it falls out of the equation. The rule "score = 0" is a single equation, and imposing one equation on a space removes exactly one degree of freedom from it. On a page (2 dimensions), fixing w1x1 + w2x2 + b = 0 leaves you free to slide along one direction only, which traces a line — 1 dimension. In a room (3 dimensions) the same single equation leaves two directions free, which sweeps out a plane — 2 dimensions. In our 120, it leaves 119. The boundary is always one short of the space it divides, because it takes exactly one equation to say where the score changes sign, and a surface of the full 120 dimensions would not divide anything — it would be the space.

One more reading of the weights, which will matter later. The weight vector w also points in a direction — the direction perpendicular to that dividing line. Moving along that direction changes the score fastest. So "what the classifier learned" and "which direction through the data separates the classes" are the same statement.

3What LDA is trying to make true

Now the models diverge. LDA starts from an assumption about how the data were generated, and then derives the best possible rule under that assumption. This is worth emphasising because it is unusual: LDA is not searching for a line that works well. It is computing the line that would be provably optimal if its assumptions held.

The assumption

Three parts, and each will come back later as a way the model can fail.

  1. Each class is a Gaussian cloud. "Gaussian" (or "normal", or "bell-shaped") means values pile up around a centre and thin out symmetrically. In 120 dimensions it means the trials of one class form a fuzzy ellipsoidal blob.
  2. Both clouds have the same shape. They can sit in different places, but they must be stretched and tilted identically. This is the assumption that makes LDA linear — drop it and you get a curved boundary instead — quadratic discriminant analysis, which comes up later under assumptions and failure modes.
  3. We know that shape and those centres. We do not. We estimate them from the data, and the damage that does is large enough to have a section of its own further down.

What "the shape of a cloud" means numerically

The shape is described by a table called the covariance matrix, written Σ. It has one row and one column per feature, so for us it is 120 × 120. Where row i meets column j sits a single number describing how features i and j vary. That number means one of two things depending on where you look:

  • On the diagonal — how much feature i varies across trials, on its own. A noisy electrode has a big number here.
  • Off the diagonal — whether features i and j move together. Two neighbouring electrodes pick up much of the same activity, so when one goes up the other usually does too: a large positive entry. Adjacent time bins do the same thing.

This matters enormously for EEG specifically. Neighbouring electrodes are not independent measurements — the skull smears each underlying source across many sensors, so a single source shows up on a dozen electrodes at once. The off-diagonal entries of Σ are large, and any method that ignores them is throwing away most of what it knows about the data.

The rule that follows

Given those assumptions, the mathematically optimal decision is: assign a trial to whichever class it is more likely to have come from — remembered or forgotten. Working that through for two Gaussians with equal covariance — this is the derivation in Welch (1939) — everything nonlinear cancels, and what survives is exactly the weighted sum this page started with, with weights

w = Σ−1 (μ1 − μ0) Blankertz et al. (2011), Eq. 9 — the whole of LDA in one line

That w is the weights — the same ones from earlier, all 120 at once. The formula does not produce something weight-adjacent that then has to be converted; hand it a set of trials and what comes back is w1 … w120, ready to drop straight into the score. Writing it as a single letter is just shorthand for the whole list, the way x was shorthand for one trial's 120 numbers.

The two pieces it is built from are worth reading separately.

  • μ1 − μ0 is the separation. A class centre is the average trial of a class. Take every remembered trial and average them feature by feature: the 120 numbers you get back describe one imaginary typical remembered trial, and that is μ1. The forgotten trials give you μ0. Each is a point sitting in the same 120-dimensional space as a real trial — just not a trial anybody recorded. Subtracting one from the other says, feature by feature, how far apart the two classes sit.
  • Σ−1 divides that by the noise. A gap between the classes only counts for as much as the wobble it has to be seen against. With a single feature no matrix is involved at all: Σ is that feature's variance σ2, Σ−1 is 1/σ2, and the formula reads (μ1 − μ0) ÷ σ2 — the gap, divided by how much that feature varies anyway. The matrix inverse is what that division turns into when there are 120 features that also vary together: the nearest thing a matrix has to a reciprocal, defined so that multiplying by Σ and then by Σ−1 gets you back where you started.

So the formula reads as separation, divided by noise. That is the entire method. The next section takes each half apart in the order you would actually compute it.

4How each weight actually gets its value

Take that formula apart in the order a person would compute it.

Part 1 — the difference of means

Average all the remembered trials, feature by feature: 120 numbers. Average all the forgotten trials: another 120. Subtract. You now have 120 numbers saying how much bigger this feature is, on average, when the word was later remembered.

If you stopped here and used those differences as the weights, you would have a perfectly reasonable classifier. It has a name — the nearest-centroid or Euclidean classifier — and it is the yellow line in the figure below. It says: weight each feature by how much it differs between conditions.

Part 2 — why that is wrong, and what Σ−1 fixes

The difference of means treats all 120 features as separate, independent pieces of evidence. They are not. Suppose two adjacent electrodes both show the remembered-minus-forgotten difference. Is that two independent votes for "remembered"? Almost certainly not — it is more likely one underlying source seen twice. Counting it twice overstates the evidence.

Multiplying by Σ−1 is the correction. It does two things at once:

  • It divides by noise. A difference of 1 µV along a direction where trials naturally scatter by 10 µV is worthless. The same difference along a direction where trials scatter by 0.5 µV is strong evidence. The inverse covariance downweights the first and upweights the second.
  • It removes double-counting. Where features are redundant, it discounts them so that correlated evidence is counted roughly once.

A useful way to hold it: Σ−1 stretches the space until all the noise is round and equal in every direction — a transformation called whitening — finds the straightforward difference-of-means line in that stretched space, then maps the answer back. In the stretched space the naive rule is correct; the multiplication is what gets you there and back.

Part 3 — so where does one individual weight come from?

This is the question that has an answer people find surprising, and it is worth stating flatly:

A weight is not a measure of how informative its feature is. A feature carrying no class information at all can receive a large weight — and removing it can make the classifier substantially worse.

Blankertz et al. (2011) demonstrate this with a constructed example worth walking through, because it makes the point concrete. Take two electrodes, FCz and CPz, which both genuinely differ between the two classes. A classifier on those two gets 15% error.

Now add a source of alpha rhythm at electrode Oz — activity that has nothing to do with the task and is identical in both classes. Because of volume conduction it leaks into the other two electrodes, at 0.4 into CPz and 0.2 into FCz. Classification on FCz and CPz collapses from 15% error to 37%: the leaked alpha is pure added noise, and it more than doubles the error.

Add Oz as a third feature and the error returns to about 16% — essentially where it started. Oz alone is useless: it contains no class information whatsoever, and a classifier given only Oz would perform at chance. But it contains a clean measurement of the contaminant, so the classifier gives it a weight whose job is to subtract the alpha back out of the other two channels.

This is what Σ−1 buys, and it is why a weight cannot be read as importance. A weight is one coefficient in a noise-cancelling recipe. Its value depends on every other feature in the set. Change which features you include and every weight changes.

5A worked example you can check by hand

Two features, so it fits on a page. Suppose across many trials we measure:

  • Forgotten trials centre at μ0 = (0, 0).
  • Remembered trials centre at μ1 = (1, 1). So the difference of means is (1, 1) — both features shifted equally.
  • Both features scatter with variance 1, and they are correlated at 0.9 — they mostly move together. So Σ = [[1, 0.9], [0.9, 1]].

The naive answer weights both features equally: w = (1, 1).

The LDA answer inverts Σ first. For a 2 × 2 matrix [[a, b], [b, a]] the inverse is [[a, −b], [−b, a]] ÷ (a² − b²). Here a² − b² = 1 − 0.81 = 0.19, so

Σ−1 = [[1, −0.9], [−0.9, 1]] ÷ 0.19 = [[5.26, −4.74], [−4.74, 5.26]]

and multiplying by the difference of means (1, 1):

w = (5.26 − 4.74,   −4.74 + 5.26) = (0.53, 0.53) same direction as the naive answer, but only 0.53 as large

Here the direction happens to be unchanged, because the setup is symmetric — but the magnitude collapsed to about half. That is LDA saying: these two features are 90% redundant, so a difference showing up in both is worth roughly one feature's worth of evidence, not two.

Now change one thing. Let the difference of means be (1, 0) — feature 1 shifts, feature 2 does not — with the same correlated Σ. Then:

w = (5.26 × 1 + (−4.74) × 0,   −4.74 × 1 + 5.26 × 0) = (5.26, −4.74)

Feature 2 shows zero difference between the classes and receives a large negative weight. This is the Oz effect in miniature. Because the two features move together, feature 2 is a good measurement of the shared fluctuation, and subtracting it cleans up feature 1. The naive rule would have given feature 2 a weight of exactly zero and thrown that away.

6The knob: shrinkage, and why it exists

Everything so far assumed we know Σ. We do not — we estimate it from the training trials, and that estimate is the weak point of the whole method.

Count what has to be estimated. A 120 × 120 covariance matrix is symmetric, so the number of distinct quantities in it is 120 × 121 ÷ 2 = 7,260. We estimate all 7,260 from about 202 trials. That is not a shortage of data; it is a different order of magnitude.

How the estimate fails — specifically

It does not fail by being randomly wrong in all directions. It fails in a systematic, predictable way, and knowing the direction of the error is what makes the fix possible.

With too few trials, the estimated covariance overstates the large variances and understates the small ones. The estimated cloud looks more elongated than the true one.

Why that is catastrophic here: LDA uses Σ−1, and inverting turns the small numbers into large ones. The directions estimated as having very little variance become directions the inverse multiplies by an enormous factor. If one of those small values is small mostly by accident, the classifier will place huge weight on a direction that is pure noise. Blankertz et al. show this directly: with 200 features, the estimated variance spectrum from 50 samples is wildly too steep at both ends, and the fit only approaches the truth around 500 samples.

The fix

Shrinkage. Rather than trusting the measured covariance, mix it with a simple, stable stand-in — a perfectly round cloud whose size is the average of the measured variances:

Σ(Γ) = (1 − Γ) × Σmeasured + Γ × νI Blankertz et al. (2011), Eq. 12; ν is the average variance, I the round stand-in

Γ runs from 0 to 1 and is the only tuning parameter LDA has:

Γwhat the model believesthe weights become
0the measured covariance, completelya full noise-cancelling filter
betweenpartly — pulled toward rounda filter, damped
1features are unrelated to each other, though still individually noisyeach feature's difference divided by its own variance

That last row is worth sitting with. Γ = 1 throws away every off-diagonal entry of Σ. What survives is each feature's difference scaled by how noisy that feature is on its own — a sensible rule, and one that is blind to every relationship between features. Every noise-cancelling weight, every Oz, goes to zero, because cancelling noise requires knowing that two features share it.

Two different things get called Γ = 1, and the difference is worth pinning down. The formula above shrinks the covariance toward νI — a sphere — so at Γ = 1 every feature is treated as equally noisy and the weights become the raw difference of means. That is Blankertz et al.'s convention. MATLAB's fitcdiscr, which is what our pipeline runs, shrinks the correlation matrix toward the identity and keeps each feature's own variance. So our Γ = 1 gives difference-of-means divided by variance, not the raw difference. Both discard all cross-feature structure, which is the point that matters here; they differ in whether the surviving weights are still scaled per feature. The live figure above follows MATLAB's convention, so it matches our pipeline.

The elegant part is that the mixing weight can be computed rather than tuned. Ledoit & Wolf (2004), in the form given by Schäfer & Strimmer (2005), derive the Γ that minimises expected error directly from the data, with no cross-validation. That combination is what people mean by "shrinkage LDA".

The idea is older than any of those. Fisher himself recommended, when the two classes have different covariances but data are scarce, using a blend τΣ1 + (1 − τ)Σ2 rather than either alone — regularisation by mixing, in 1936. We have this second-hand, from the opening pages of Cortes & Vapnik (1995), rather than from Fisher directly.

Our pipeline runs Γ = 1 — the maximum, the row that discards all covariance structure. In Blankertz et al.'s own sweep, Γ = 1 was the worst setting they tried (36% error, against 18% at Γ = 0.05). We are not necessarily wrong to use it: at 1.7 trials per weight there may be nothing trustworthy to keep, and Raudys & Jain's sample-size table says a means-only classifier needs about a third the data of a full one. But it is a real choice with a real cost, and the trial-count work exists partly to price it.

7Reading the weights — the mistake almost everyone makes

You have a trained classifier. You have 120 weights. The natural next move is to plot them on a scalp map and say where in the brain the memory effect lives.

That is invalid, and the reason is worth understanding properly.

There are two different maps, and they answer different questions.

the patternthe filter
what it is difference of means, μ1 − μ0 the classifier weights, Σ−1(μ1 − μ0)
question it answers where does the signal show up? how do I best extract it?
safe to interpret? yes — this is the ERP map no
looks like smooth, one or two broad blobs intricate, sign-flipping, large values in uninformative places

The Oz example earlier is exactly this: Oz gets a big weight in the filter and is flat in the pattern. Reading the filter as a brain map would put a memory effect in occipital cortex, when what is actually there is alpha rhythm being subtracted out.

Haufe et al. (2014) — filed here as papers/Haufe_Etal_2014.pdf — is the standard treatment, and it gives the conversion: to get an interpretable map from a trained linear model, multiply the weights back by the covariance. The general rule:

Interpret patterns. Evaluate filters. If you want to say where in the brain something happens, plot the difference of means. If you want to know whether the information is decodable at all, use the classifier's accuracy. Never read the weight vector as anatomy.

There is a consequence worth stating carefully, because it is easy to get slightly wrong. Under the shrink-toward-a-sphere convention, Γ = 1 makes the filter equal the pattern — the weight map becomes the difference of means and is safe to read. Under MATLAB's convention, which is ours, Γ = 1 makes the filter the pattern divided by each feature's variance: much closer to interpretable than a full filter, but still not a difference map, and still capable of exaggerating a quiet feature. Either way the direction of the trade is the same — the settings whose weights are easiest to interpret are the ones that have thrown away the most information.

8What breaks when trials are scarce

This section appears on both deep-dive pages, because the problem is shared and the comparison is the interesting part.

The classifier has to pin down 120 weights from about 202 trials — fewer than two examples per weight. What that does is not subtle. The learned direction is the true direction plus estimation noise, and with p features and n trials the noise grows like p/n.

Raudys & Jain (1991) worked out the sample sizes needed to keep this under control. To keep expected error within 50% of its best achievable value:

classifierwhat it estimatestrials needed
Euclidean — means only2 × 120 numbers1.2 × features ≈ 144
our Γ = 1 — means + one variance each+ 120 numbersbetween the two
full LDA (Γ = 0)+ 7,260 covariance numbers4.0 × features ≈ 480
separate covariance per class+ 7,260 more10–32 × features

We train on 202. So full LDA is roughly a factor of 2.4 short, and even the means-only version is marginal. That 1.2-versus-4.0 gap is the entire case for shrinkage, derived analytically decades before we measured the same thing by simulation. Raudys & Jain do not tabulate the middle row — diagonal LDA is not one of the classifiers they costed — but it estimates 120 numbers more than the Euclidean rule and 7,260 fewer than the full one, so it necessarily sits between them.

9Assumptions, variants, and failure modes

If the classes are not Gaussian

LDA is fairly forgiving here — it tends to work on non-Gaussian data because the rule only depends on means and covariances, not the full shape. But it is genuinely wrong when a class is multi-modal: if "remembered" is really two different processes with two different signatures, their average is a point between them that may describe no actual trial.

Worth flagging for our data specifically: our real EEG features are strongly non-Gaussian. Measured kurtosis is about 23, where a Gaussian is 3 — meaning far more extreme values than the model expects. That is a known gap between our simulations and our data.

If the two classes have different shapes

Then the optimal boundary is curved, and the model for it is quadratic discriminant analysis (QDA), which estimates a separate covariance per class. It is more flexible and almost always worse in practice here, because it doubles an estimation problem that is already hopeless — Raudys & Jain put it at 10–32 × features. Blankertz et al. checked the equal-shape assumption for ERP data and found it approximately satisfied, which is the empirical justification for staying with LDA.

If the classes are unbalanced

Our study-phase data is: many more remembered than forgotten words. LDA handles this in the bias term b, which absorbs the prior probability of each class. If you leave it alone the model will lean toward predicting the common class. Since we score with AUC, which sweeps over every possible threshold, the bias does not affect our reported numbers — but it does affect any single accuracy figure, which is one reason accuracy is a poor measure here.

Things LDA is secretly the same as

  • Fisher's discriminant. Fisher (1936) asked for the direction maximising between-class separation over within-class spread, with no probability model at all, and got the same answer. Two derivations, one formula.
  • Least-squares regression on the labels. Regressing a 0/1 label on the features gives the same direction, up to scale.

Practical notes

  • Feature scaling does not matter. Σ−1 already normalises by variance, so rescaling a feature rescales its weight and leaves the answer unchanged. This is not true of SVM, whose assumptions section says why.
  • It is deterministic. Same data, same answer, every time — no random initialisation, no seed. Our committed LDA reference file has never changed; the SVM one had to be regenerated.
  • It is fast, and one-shot. Compute two means, one covariance, invert it. No iteration.
  • It gives calibrated probabilities under its assumptions, which SVM does not.
